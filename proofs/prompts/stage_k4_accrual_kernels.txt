The targets are three new associated functions of `V16Core` in src/v16.rs that hold the per-segment arithmetic of a market's accrual (both accrual entry points, `accrue_asset_to_not_atomic` and `accrue_asset_path_to_not_atomic`, call them), and the existing `V16Core::kernel_adl_scaled_accrual_index_deltas` that the third one calls. Each carries a `kani::ensures` contract (the `cfg_attr` right above it); model checking covers those contracts only for small or near-extreme inputs (the wide products put full-width checks beyond it). Prove each property for every input over the whole types, about the deployed function bodies (no cfg(kani), default features, this crate's release profile with overflow-checks = true). Exact integers throughout; `FD = FUNDING_DEN` (10^9).

Part 1. The oracle bound of one accrual segment: `kernel_accrual_price_move_within_cap(old_price, new_price, max_price_move_bps_per_slot, segment_dt)`.
- KA.contract: it satisfies its ensures clause.
- KA.nopanic: no execution panics.
(The single-segment accrual calls it for every segment in which equity moves; with KA.contract, an accrual that returns `Ok` never moved the effective price by more than `max_price_move_bps_per_slot * segment_dt / MAX_MARGIN_BPS` of the old price, whatever price was reported.)

Part 2. The funding amount of one segment: `kernel_accrual_funding_num(funding_rate_e9, segment_dt, effective_price, funding_active)`.
- KN.contract: it satisfies its ensures clause.
- KN.nopanic: no execution panics.

Part 3. The K/F index update of one segment: `kernel_accrual_index_update(k_long, k_short, f_long, f_short, a_long, a_short, price_delta, funding_num)`, which adds the deltas of `kernel_adl_scaled_accrual_index_deltas(price_delta, funding_num, a_long, a_short)` to the four indices.
- KI.contract: it satisfies its ensures clause.
- KI.nopanic: neither function panics on any input.
- KI.floors: if it returns `Ok((kl, ks, fl, fs))`, then `fl - f_long == floor(-funding_num * a_long / FD)` and `fs - f_short == floor(funding_num * a_short / FD)` (exact, rounded toward minus infinity), in both branches of the function (whether or not `funding_num` is a multiple of `FD`).
- KI.funding_conserves: if it returns `Ok((kl, ks, fl, fs))` with `a_long >= 1` and `a_short >= 1`, write `dl = fl - f_long` and `ds = fs - f_short`. Then `dl * a_short + ds * a_long <= 0` and `dl * a_short + ds * a_long > -(a_long + a_short)`. (Per unit of effective position, `dl / a_long` on the long side and `ds / a_short` on the short side: funding moves value from the paying side to the receiving side and never creates any; the receiving side gets at most what the paying side pays, and the difference is less than one index unit per side.) If `funding_num` is a multiple of `FD`, then `dl * a_short + ds * a_long == 0`.
- KI.mark_to_market: if it returns `Ok((kl, ks, fl, fs))` and `a_long == a_short`, then `(kl - k_long) + (ks - k_short) == 0` (mark to market moves value between the sides and creates none).
- KI.path: if it returns `Ok((kl, ks, fl, fs))`, then `kl - k_long == price_delta * a_long` and `ks - k_short == -(price_delta * a_short)` (exact integers). Consequently, if two successive calls with the same `a_long` and `a_short`, the second starting from the first one's results, with price deltas `d1` then `d2` (any funding amounts) both return `Ok`, the K indices after the second are `k_long + (d1 + d2) * a_long` and `k_short - (d1 + d2) * a_short`; prove this two-step statement as well. (A jump to a price and any chain of steps to the same price move the K indices by the same amount.)

Part 4. The program's price clamp. The file `wrapper_ebcded58/oracle_v16_clamp.rs` is a verbatim copy of two pure functions of the deployed program (module `oracle_v16` of percolator-prog `src/v16_program.rs`); the program computes the price it asks the engine to accept with them, for a crank and for a price a trade reports. The file is not part of the engine crate and needs only `core`: build it on its own (for example as a one-module library crate, release profile with overflow-checks = true). Exact integers.
- KC.nopanic: neither `clamp_toward_engine_dt` nor `effective_price_from_target` panics on any input.
- KC.envelope: for all u64 inputs with `p_last > 0` and `target > 0`, `r = clamp_toward_engine_dt(p_last, target, cap_bps, dt_slots)` satisfies `min(p_last, target) <= r <= max(p_last, target)` and `|r - p_last| * 10000 <= p_last * cap_bps * dt_slots`.
- KC.reaches: if in addition `|target - p_last| * 10000 <= p_last * cap_bps * dt_slots`, then `r == target` (a move inside the envelope is taken in full).
- KC.select: `effective_price_from_target(anchor, target, max_change_bps, dt_slots, exposed)` is `clamp_toward_engine_dt(anchor, target, max_change_bps, dt_slots)` when `exposed` and `target` otherwise.
(Model checking gave no verdict on KC.envelope within 50 minutes, even with caps and segment lengths below 65,536: the 128-bit saturating products are beyond it.)
