New task on the same project, continuing layer T. Two files are uploaded with it: aristotle/transition_shape_spec.md (the entry points and the class each was found to have) and aristotle/header_write_sets.md (the eighteen checks H0 to H17 of validate_shape in a default build, and for each entry point without a check of its own the header fields it can write). This task is about the entry points of class "local" and "frame": they do NOT call validate_shape in a default build, so their property needs an argument about every write, but the argument is small. Record each finished property before starting the next, so finished results are kept if the task stops early.

Definitions. For a market view m (a header and a slice of market slots), H(m) means: MarketGroupV16View::validate_shape evaluated on m returns Ok(()) in a default build (the audit-scan feature is off, so the block that calls validate_shape_full_audit_scan is compiled out and validate_shape_audit_scan returns Ok(()) without reading anything). For a header account h alone, Hh(h) means: every check of that same function body except its first statement (the call to validate_dynamic_market_slots_len_static, the only check that reads the slice of market slots) passes on h. So H(m) holds exactly when Hh(m.header) holds and m.markets.len() == m.header.asset_slot_capacity and m.header.asset_slot_capacity >= m.header.config.max_market_slots. Please confirm this decomposition, and the list H0 to H17 with the fields each check reads, against the source before using them, and say so if the source differs.

Every property of this task has the form: for all inputs and all starting states with H (or Hh), if the call returns Ok(_), then H (or Hh) holds of the state the call leaves behind. State in the summary the exact set of header fields each Ok path writes.

Part 1, class frame, on MarketGroupV16ViewMut. The claim is that no written header field is read by a check.
- T47 register_empty_materialized_portfolio_not_atomic and T29 deregister_empty_materialized_portfolio_not_atomic. I expect the only write to be header.materialized_portfolio_count.
- T33 finalize_side_reset_not_atomic. It has an early Ok path (the side is already Normal) that should write nothing. The other Ok path writes one asset record through set_asset_state and raises header.risk_epoch. Establish what set_asset_state writes in the header (I expect only resolved_payout_blocker_count, through update_resolved_payout_blocker_total), that no check reads a written field, and that the length of the slice of market slots is unchanged. (This function also calls validate_header_aggregate_totals in every build; the property does not need it.)

Part 2, class local, on MarketGroupV16ViewMut. The claim follows from guards inside the function.
- T09 advance_resolved_slot_not_atomic. One write, header.current_slot. H8 (slot_last <= current_slot) and H13 (last_asset_activation_slot <= current_slot when asset_activation_count != 0) need the new value not to be below the old one: kernel_advance_resolved_slot. Then the two ScanProgress returns of T10 advance_terminal_slab_not_atomic, which perform only this write after a validate_shape() at entry.
- T02 accrue_asset_to_not_atomic. Writes current_slot, slot_last, loss_stale_active, oracle_epoch, funding_epoch and one asset record. I expect: current_slot becomes max(current_slot, now_slot), so it does not fall; slot_last becomes the asset's new slot_last, which is the old one plus min(now_slot - old, max_accrual_dt_slots) and so at most now_slot (the function refuses now_slot below the asset's slot_last); loss_stale_active is the result of encode_bool. That gives H2, H8 and H13 with no assumption beyond H at entry. Note that H8 here does not need the asset's slot_last to have been at most current_slot before the call.
- T01 accrue_asset_path_to_not_atomic. Same fields. I expect: the function refuses now_slot below current_slot and then writes current_slot = now_slot; the asset's slot_last advances by the number of steps, which is at most now_slot minus the old value; loss_stale_active from encode_bool.

Part 3, class local, on the header account MarketGroupV16HeaderAccount, where no slice of market slots is in scope, so the statement is about Hh.
- T38 grow_asset_slot_capacity_not_atomic(new_asset_slot_capacity, new_max_market_slots): for all inputs and all headers h with Hh(h), if the call returns Ok(()), then Hh holds of the header it leaves, its asset_slot_capacity equals new_asset_slot_capacity, its config.max_market_slots equals new_max_market_slots, and new_asset_slot_capacity >= new_max_market_slots. (So H holds for every view of that header whose slice has exactly new_asset_slot_capacity slots; the caller resizes the slice.) The step that needs care: the function stores V16ConfigAccount::from_runtime(&config) for a config whose max_market_slots was raised, and Hh requires that config.try_to_runtime_shape() succeeds on what was stored. Prove that round trip from the source of from_runtime, try_to_runtime_shape and validate_public_user_fund_shape; do not assume it. If it does not hold for some accepted input, that is a finding: report the input.
- T05 activate_empty_market_slot_not_atomic(asset_index, slot, authenticated_price, now_slot): for all inputs and all headers h with Hh(h), if the call returns Ok(()), then Hh holds of the header it leaves, and asset_slot_capacity and config are unchanged (so H is preserved for the same slice length). The claim rests on: now_slot >= the old current_slot on every Ok path; next_market_id stays nonzero; asset_activation_count becomes nonzero and last_asset_activation_slot == current_slot == now_slot afterwards.
- T03 activate_empty_asset_slot_not_atomic is a call to T05: restate its property from T05.
