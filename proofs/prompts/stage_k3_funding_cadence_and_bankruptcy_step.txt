Two targets in src/v16.rs, both pure (no account or market state). Prove each property for every input over the whole types, about the deployed function bodies (no cfg(kani), default features, this crate's release profile with overflow-checks = true). Exact integers throughout: `D = SOCIAL_LOSS_DEN` (10^21), `den = a_basis * POS_SCALE` as a mathematical product, and `fl(x, y) = floor(abs_basis * (y - x) / den)` rounded toward minus infinity.

Part 1. Funding settlement of one leg (free functions `scaled_adl_delta_fast`, `f_snap_after_settlement`). A leg with absolute basis `abs_basis` and ADL basis `a_basis` settles funding from its snapshot `f_snap` to the funding index `f_now`. The caller (`leg_kf_delta_components_for_settlement_from_asset`) computes `f_delta = scaled_adl_delta_fast(abs_basis, a_basis, f_snap, f_now)`, or `wide_signed_mul_div_floor_from_k_pair(abs_basis, f_snap, f_now, den)` when that returns `None`, and then the next snapshot `f_snap_after_settlement(abs_basis, a_basis, f_snap, f_now, f_delta)`. The snapshot is advanced only by the F distance whose value covers what was paid, so the unpaid sub-atom value is carried to the next settlement instead of being floored away.

- KF.delta: `scaled_adl_delta_fast(abs_basis, a_basis, then, now)` never panics, and if it returns `Some(x)` then `x == fl(then, now)` with `den = a_basis * POS_SCALE`. (With E5 this makes the caller's `f_delta` exactly `fl(f_snap, f_now)`.)
- KF.nopanic: no execution of `f_snap_after_settlement` panics.
- KF.carry: assume `abs_basis > 0`, `den <= u128::MAX` and `f_delta == fl(f_snap, f_now)`. If the call returns `Ok(s)`, then (i) `s <= f_now` and `abs_basis * (f_now - s) < den` (what stays unpaid is worth less than one atom and is never a debt), and (ii) `f_delta * den <= abs_basis * (s - f_snap) < f_delta * den + abs_basis` (the snapshot moved by at least the value that was settled, and by less than one more F unit's worth).
- KF.ok: under the hypotheses of KF.carry, state exactly when the call returns `Err`, and prove that it returns `Ok` whenever in addition `|f_now - f_snap| + den <= i128::MAX` and `f_now - den >= i128::MIN`. (The function re-checks its own result and returns `Err(ArithmeticOverflow)` when the check fails; this property says the check never fires on exact inputs, so a settlement cannot get stuck on it.)
- KF.cadence: fix `abs_basis > 0` and `a_basis` with `den <= u128::MAX`. Take a snapshot `s_0`, any `n >= 1` and any index values `b_1, ..., b_n` (in any order, not necessarily monotone). For each `i`, let `d_i = fl(s_(i-1), b_i)` and let `s_i` be the `Ok` result of `f_snap_after_settlement(abs_basis, a_basis, s_(i-1), b_i, d_i)`; assume all `n` calls return `Ok`. Let `T = fl(s_0, b_n)`, the amount one settlement from `s_0` straight to `b_n` would move. Then `d_1 + ... + d_n <= T`, and `(T - (d_1 + ... + d_n)) * den < den + n * abs_basis`; and if `den` is a multiple of `abs_basis`, then `d_1 + ... + d_n == T`. (Settling more often never credits an account more, and never charges it less, than settling once; the difference is bounded by the rounding of each step.) State and prove it about the function itself, by induction on `n`, not about a model of it.

Part 2. The size of one bankruptcy-residual booking step: `V16Core::kernel_bankruptcy_residual_step_capacity(b_now, weight_sum, rem, residual_remaining, chunk_atoms)`, an associated function new in this revision. The engine books the returned chunk `c` onto the opposite side's B index with `V16Core::apply_bankruptcy_residual_chunk_to_loss_side(&mut asset, opp, c, residual_remaining)`, which computes `delta_b = floor((c * D + rem) / weight_sum)` (via `social_loss_book_split`), refuses with `Ok(None)` when `delta_b == 0` or when `b_now + delta_b` overflows, and otherwise adds `delta_b` to the index and stores the new remainder. A returned 0, or a refusal, makes the caller declare the market in Recovery with reason `BIndexHeadroomExhausted`.

- KR.contract: the function satisfies its `kani::ensures` clause (model checking covers it only with `b_now` within 255 of `u128::MAX` and the other inputs of 8 bits).
- KR.nopanic: no execution panics; state exactly when it returns `Err`.
- KR.fits: if it returns `Ok(c)` with `c > 0`, then `floor((c * D + rem) / weight_sum) <= u128::MAX - b_now` (booking `c` cannot overflow the index).
- KR.zero: if `residual_remaining > 0`, `weight_sum > 0` and `chunk_atoms > 0` (config admission refuses a zero chunk), it returns `Ok(0)` exactly when `floor((D + rem) / weight_sum) > u128::MAX - b_now`, that is, when booking even one atom would overflow the index. (Recovery for lack of headroom is declared only when the headroom really is exhausted.)
- KR.books: assume `weight_sum <= D` (the engine's asset-shape validation refuses a larger weight sum), `rem < D` (every write of the remainder is a remainder modulo a weight sum of at most `D`, or zero) and `chunk_atoms <= MAX_VAULT_TVL` (config admission). If the function returns `Ok(c)` with `c > 0`, then for every asset state whose fields for side `opp` (`b_long_num`, `loss_weight_sum_long`, `social_loss_remainder_long_num` for `Long`; the `_short` fields for `Short`) are `b_now`, `weight_sum` and `rem`, the call `apply_bankruptcy_residual_chunk_to_loss_side(&mut asset, opp, c, residual_remaining)` returns `Ok(Some(o))` with `o.booked_loss == c`, `o.delta_b >= 1` and `o.remaining_after == residual_remaining - c`. (A step the capacity function admits is always booked: a bankrupt close never falls into Recovery while the index has room.)
