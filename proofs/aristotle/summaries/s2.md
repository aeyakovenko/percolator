## Trade-execution pilot (engine d1fa39f6), stopped early on budget

All three methods are taken at `T = ()`, the only instantiation: `MarketGroupV16ViewMut<'_, ()>` in a release build with `overflow-checks = true`, default features and no `cfg(kani)`. Only one Part 4 contract is fully proved; every other property is open. Each Properties row says what is proved and what blocked it.

**Proved**
- **TC8** (`kernel_trade_side_oi_cap_gate`): proved from its body, in both forms (the stated result if it returns; and no panic). The earlier K17 proof is reused after checking that the compiled body is the same. While doing this I found and fixed an error in my own statement: `InvalidLeg` is error variant 4, not 5.

**Proved only under assumptions (row stays open)**
- **TC3** (`require_asset_risk_change_allowed`): proved from its body, and it cannot panic outside its callees. It assumes two contracts that are not verified:
  - `asset_state` reads the slot and writes nothing;
  - `asset_risk_increase_gate` returns a valid `V16Result<()>`.

**Unresolved: what got done and what was expensive**
- **TC1:** the callees `account_capital_to_insurance` and `validate` are proved, and most of the body. The last steps after `validate` returns are open. Cost: the byte-level model of the 9419-byte account and frames of about 100 locals.
- **TC6:** body proof partly drafted. Cost: 4 protected retags and very large compiled types.
- **TC2, TC7, TC4:** not attempted. TC2 has about 15 callees; TC7 reaches about 705 functions, including `array::map` with closures.
- **TB.flag, TB.checked:** the helpers are proved (`len`, `is_empty`, the `?` helpers, `decode_bool`, both `as_view`). The walk of the body is open: a loop over `requests` with two account views rebuilt each iteration, 25 calls and 4 protected retags.
- **TF.margin, TF.locked, TF.frame:** the helpers and the call rules for TC9 and the margin checks are proved. The body walk is open (83 blocks, about 88 paths).
- **TA.fee, TA.conservation, TA.positions, TA.gate, TA.frame:** the pure step from the callee contracts' conclusions to all five properties is proved. The body walk is open: 139 blocks, 296 locals, 25 calls and 23 `?` exits.
- **TA.nopanic:** open, and needs the same walk. The arithmetic sites I checked: the body has none of its own except two `checked_sub(..).ok_or(..)?`, which return `Err` instead of panicking.
- **TC5, TC9:** not attempted.

**What made it expensive** was not the stepping. It was:
- the size of the bodies and the number of `?` exits;
- the state model of the 9419-byte account;
- retags and reborrows;
- above all, shared borrows of the caller's local variables, which must be handed back on every exit, including a panic.

**Findings**
1. **TA.positions is false as stated.** If a lookup has `next_q == current_q`, the position change does nothing. No code (including TC2 and TC5) compares `current_q` with the stored leg, so the account can keep a position other than `next_q`. I added the precondition "`next_q != current_q` or the stored position already equals `current_q`".
2. **TC4 needed a stronger statement:** the body also writes a field of the slot of `asset_index`, so I added "no other slot is written".
3. **TC5 needed a stronger statement:** I added "nothing is written when `delta_q == 0`".
4. **The contracts needed four changes to be usable at all:**
   - methods that borrow a caller's local variable (`&view`, `&trade_preflight`) must give the borrow back if they panic;
   - methods taking `&self` must accept a shared part of the view;
   - empty `requests` and market slices still need a valid pointer;
   - the market slice is assumed smaller than \(2^{56}\) bytes. This is a standard assumption that applies to all the Rust results here.
5. **TF.order (answered from the source, not proved):**
   - `certified_initial_req` cannot rise, because it is only copied.
   - `certified_equity` can plausibly fall when the long account has positive PnL and claims on a source domain whose state the short account's lien changes. I did not read the per-domain readers, so that step is inferred.
   - The short lien may also raise `risk_epoch`, which leaves the long certificate stale while it is still marked valid.
6. **TB.flag:** if the opaque call panics, the flag is not restored. The property covers returns only, as you asked.

**Verification boundary.** Verified: TC8 alone. TC3 holds conditionally on the two callee contracts above. Everything else listed is unverified.

The public statements are in `Spec/Trade.lean`, `Spec/TradeContracts.lean`, `Spec/TradeRep.lean` and `Spec/TradeConst.lean`. The harness that instantiates the generic impl is `harness/trade_exec`.
